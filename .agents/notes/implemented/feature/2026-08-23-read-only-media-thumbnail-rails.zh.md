# Agent Note: 只读媒体缩略图栏

Status: implemented

[English](2026-08-23-read-only-media-thumbnail-rails.md) | 中文

## Problem

对话之外的浏览器功能需要复用粘贴聊天图片所用的紧凑横向分页视觉审查栏。若每个消费方各自实现 64px 几何、滚轮处理、边缘箭头和响应式行为，样式与交互会逐渐分叉；而现有 atom 强制使用图片元素和删除动作，即使持有方展示的是不可变的生成产物。

## Decision

`@monotykamary/dsh-client-ui-attachment/client` 以同一个 `AttachmentRail` atom 服务可变输入框草稿和持有方提供的只读媒体。`AttachmentRailItem.previewKind` 选择图片或视频标记，省略时仍按图片处理以保持兼容；视频行使用给定 URL 并显示播放标记。`onRemove` 与 `removeLabel` 一并成为可选项，因此省略删除动作时不会产生隐藏或禁用的删除控件。授权、加载、媒体生命周期、打开动作和全屏呈现仍由持有方负责。

对话附件流水线仍只接受图片。只读视频呈现不会新增视频摄取、持久媒体字段、Session 事件或聊天历史视频 renderer。

## Alternatives considered

**由每个消费方复制附件栏。** 这样无需扩展共享 atom，但会重复非平凡的滚动、尺寸观察、减少动态、触屏和无障碍行为，并让视觉模式产生分叉。

**新增独立的产物附件栏 atom。** 第二个组件只在缩略图类型和删除动作上有差异，却要并行维护同一套交互。

**把对话附件扩展到视频。** 这需要主机限制、持久媒体记录、模型／提供方能力决策和 Session 投影变更，而只读审查不需要这些能力。

## Consequences

外部功能可以为不可变图片和视频复用与聊天粘贴完全一致的缩略图几何，而无需伪装成输入框草稿。现有调用方保留图片和删除行为。附件栏既不解释也不持久化视频字节，全屏轮播策略仍属于消费功能。附件 atom 测试固定视频标记、播放图标、只读时不渲染删除控件，以及既有分页行为。
