# Agent Note: 设置弹窗的移动端全屏表单（sheet）布局

Status: implemented

[English](2026-08-21-settings-modal-mobile-sheet.md) | 中文

## Problem

设置弹窗是唯一没有紧凑尺寸适配的表面。在 768px 以下，应用把侧边栏轨道收进一个 portal 抽屉，但设置仍然保持居中的双栏弹窗：188px 导航栏加一列内容区，宽度上限为 `calc(100vw - 48px)`。在 375px 视口下，弹窗缩到 327px，导航栏占掉其中 188px，留给内容区只剩约 70px 的缝隙——每个设置列表和编辑器都被压得无法使用，两侧 24px 边距也浪费了手机的屏幕空间。命令面板和终端都用媒体查询适配了紧凑视口；设置一直没有。

## Decision

`ui-settings-general` 在 `SettingsRoot.module.css` 中用一个纯 CSS 的 `@media (max-width: 767px)` 代码块渲染 sheet 布局，与紧凑抽屉的断点对齐（`SIDEBAR_DRAWER_VIEWPORT = 768`）。在断点以下，弹窗变成一个铺满视口的表单：遮罩层拉伸到视口，面板去掉 800px 宽度上限、圆角和 48px 边距，`flex-direction: column-reverse` 让头部行（操作按钮 + 关闭）保持在顶部，同时导航占据表单底部。桌面端的 DOM 完全不动——同样的标记、同样的角色、同样的无障碍名称，因此所有既有的分页切换和关闭断言仍然通过。

188px 导航栏变成横跨底部的 36px 胶囊芯片条，可横向滚动，并复用 workbench/trajectory 的滚动条隐藏惯用法。选中与悬停填充复用与导航栏相同的 `--dsw-specific-sidebar-nav-item-*` token，让两个断点共享同一套分区词汇。标题节点（dialog 的 `aria-labelledby` 目标）保持挂载，但像关闭座那样被裁剪隐藏：在保留无障碍名称的同时，视觉标题不再占据表单的排版位置。安全区 inset 为表单顶部和底部芯片条的底部留白，避免刘海屏裁切任一边缘。

分区内容保持桌面布局不变；只改 sheet 的壳。整处改动集中在一个模块的 CSS 中。

## Testing

- 包内新增 `styles.client.spec.ts` 钉住 sheet 契约：断点存在、全屏面板、列反转、安全区留白、横向滚动且无滚动条的导航条，以及桌面 800px/188px 几何不受影响。
- `apps/web/tests/settings-chrome.e2e.ts` 新增几何测试：在 375x812 视口打开抽屉，经由抽屉打开设置并测量表单：面板铺满视口、导航底部贴齐面板底部、设置列在胶囊条上方结束、页面不产生横向滚动——然后从胶囊条切换分区，并用 Escape 关闭。
- 既有的 command palette 与设置 e2e 黄金文件在 1680px 视口运行；该媒体查询在那种宽度不生效，因此这些表面不受影响。

## Alternatives considered

- **保留双栏弹窗，只在手机上加宽面板。** 缩窄导航栏或内容只是把挤压挪了个位置；在 375px 下，不可能同时保留可读的导航栏和可用的设置区。
- **用 JS `useMediaQuery` 切换渲染一套独立的移动组件。** 外壳没有任何 JS 布局逻辑，而且所有同级的覆盖层（modal、palette、sheet）都把响应式规则放在 CSS 里；第二套组件树会重复 slots、无障碍接线和测试，却没有任何行为收益。
- **带拖拽手势的半屏底部表单。** 应用的 Sheet、Modal 和 palette 都是铺满遮罩层的整高元素；可拖拽的半高表单将是同类中唯一的一个，而且需要手势接线，但产品并没有提出这种需求。

## Consequences

- 设置弹窗在手机上可用：全高表单、拇指可及的胶囊导航、全宽的分区列。
- 弹窗在不同断点间保持同一个 DOM 和同一套无障碍名称；只有几何不同。
- 桌面几何完全不变——媒体查询不触及它。
- 导航行溢出时 widget 会横向滚动；在当前分区名单下，胶囊行一次就能放得下。
