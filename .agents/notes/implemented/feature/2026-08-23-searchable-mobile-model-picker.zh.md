# Agent Note: 可搜索的移动端模型选择器

Status: implemented

[English](2026-08-23-searchable-mobile-model-picker.md) | 中文

## Problem

Composer 的模型 trigger 位于控制行尾端。其右侧锚定的菜单采用内容宽度且只设置最大值，因此较长的模型名称可能让菜单左边缘落到手机 viewport 之外。当用户已经知道模型 id 时，较大的 Provider 目录仍要求逐个浏览全部分组与显示名称。

## Decision

模型菜单采用相对 viewport 的宽度并以 420 px 为上限；它测量渲染后的卡片，仅在右侧锚点会造成裁切时平移，从而与每个水平边缘保持 12 px 间距。现有的锚定高度 hook 继续限制菜单在 Composer 上方向上增长，并在 viewport 滚动或尺寸变化时重新测量。

模型面板顶部是自动聚焦的客户端搜索框。查询以不区分大小写的子串匹配模型 id、显示名称、Provider 显示名称和描述，同时保持 Provider 与模型顺序。匹配行会在 id 与显示名称不同时单独显示 id；空结果使用独立提示，且仅剩一个模型时按 Enter 会选择它。关闭菜单或离开模型面板会清除查询。

## Alternatives considered

**只限制菜单宽度。** 宽度上限可以避免卡片过宽，但无法修正左边缘已经越出窄 viewport 的右侧锚定卡片，也无法让大型目录可搜索。

**通过宿主 RPC 搜索。** 用于选择的完整建议目录已经加载。每次查询都发请求会增加延迟、取消和失败状态，却不会减少初始目录 payload。

**改用命令面板取代两级选择器。** 这会从 Composer 控制中移除模型与推理等级的关系，并让推理等级选择变成一次独立交互。

## Consequences

模型面板在手机宽度下保持在屏幕内，模型 id 可以直接搜索，且选择与目录 contract 不变。筛选复杂度与已加载目录线性相关，并且只属于临时浏览器状态。单元测试固定匹配、自动聚焦、空结果和单结果 Enter；组装应用的 390×844 浏览器场景固定可见菜单与控件几何关系。
