# Agent Note: Interactive Web terminals

Status: implemented

English | [中文](2026-08-19-interactive-web-terminals.zh.md)

## Problem

The Web UI could render completed terminal-style Tool results but had no human-to-PTY path. Reusing model terminal operations would preserve line-normalized scrollback and send-readiness semantics rather than the raw byte stream, resize, alternate buffer, and sustained input latency that interactive applications require. A separate terminal server would duplicate Agent ownership, workspace/sandbox policy, process cleanup, Web trust, and identity admission. The shell also had no bottom region whose hidden state could preserve a live attachment, while the right Workbench needed Terminal to remain an independently registered feature.

## Decision

`dsh-base` mounts one Host `ctx.terminals` registry and `terminal-bash` backend. The registry already keys every session and cleanup by the exact owning Agent, so all presets inherit one capability without publishing service instances in child preset realms. Model tools remain preset contributions; browser use does not add a Tool or model-visible input. Browser-created PTYs start in the selected Session cwd, request the user's native login shell with its startup files and prompt, advertise 256-color truecolor support through both the subprocess terminal type and child environment, and use reserved `web-bottom-*` or `web-right-*` names. Model terminal sessions retain the configured controlled shell and readiness framing. The browser transport resolves the admitted Session owner before every list/open/attach/kill operation and refuses attachment to sessions outside those namespaces.

`dsh-client-connection` exposes an effect-owned Host-only `upgrade()` registration. It validates an exact absolute path, applies the shared Host/Origin fence and optional identity authority, and gives the protocol owner the admitted identity plus raw request/socket/head. `dsh-terminal-web` owns `/api/terminal`: the first JSON text frame selects one operation; live sockets carry UTF-8 input and PTY output as binary frames, with resize/kill/status controls as JSON. Output batching, payload limits, handshake deadlines, WebSocket buffered-byte limits, ordered attachment operations, and awaited teardown bound each connection. Independent sockets may attach one PTY concurrently: the backend fans replay and live bytes out to every viewer, serializes input, and transfers resize ownership to the most recently interactive viewer while retaining each viewer’s last grid for handoff.

`ui-layout` declares a session-scoped `bottom-panel` under the center column. Its transient store controls a 280px first-open default, a remembered 160–520px drag height, and a 240px conversation floor. The slot host remains mounted at zero height when closed, so hiding the panel does not terminate or detach the shell. `ui-terminal` registers independent bottom and right Workbench placements, contributes a generic PanelBottom Session-header toggle, and shares browser-local appearance preferences across them. Its appearance editor uses the shared modal plus compact product menus and toggles instead of browser-native controls that scale inconsistently. Each placement holds one active attachment and leaves inactive processes alive. Tab close removes UI state before awaited Host cleanup, shell exit retires the same tab, and explicit create and kill actions remain available.

The xterm implementation adapts localterm revision `8de7394eb06cf562985d8f82d5a8145863cb8ecd`. Its frame-aware output scheduler, scroll anchoring, font-probed ligature joiner, Unicode width correction, patched WebGL emoji-color control, and image-resolution patch remain together. Dynamic client bundles support lifecycle-owned `*.global.css` and package-resolved Fontsource styles. Fontsource's WOFF fallback is removed, WOFF2 files are embedded as watched data URLs, and the terminal plugin ships the complete localterm font-family menu without a sidecar asset route. The selected face is loaded before xterm remeasures cells, xterm retains its own unstretched canvas size, and the inner surface and outer viewport are observed throughout panel transitions. A resident collapsed bottom surface does not publish readiness until the layout owner reaches its target height, so initial PTY allocation uses the settled grid; the rendered screen remains observed so loaded-font width changes trigger another fit instead of clipping rightmost columns. The validated opening grid crosses the Web handshake and terminal capability into PTY allocation; the latest fitted grid is replayed after attachment because resize observation can run before WebSocket readiness; the selected terminal palette owns every body, xterm, viewport, and gutter layer. The code imports the patched addon ESM artifacts explicitly because each package's CommonJS `main` remains unpatched.

The terminal toolbar and panel placement retain T3 Code attribution at revision `a4cc1367b03ee0c1dc2b50fceac81ef5e63212e2`; localterm and T3 licenses plus every embedded Fontsource family’s copyright and full OFL/UFL text are generated into `THIRD_PARTY_NOTICES.md`.

## Verification

Package tests cover native human-shell selection, controlled model-shell preservation, terminal resize through local and E2B providers, ready-state grid replay, multi-viewer raw replay/live fan-out and resize handoff, exact-Agent authorization, Connection upgrade trust and disposal, WebSocket framing/backpressure, browser protocol parsing, preference persistence, panel actions, layout resize/concession, and the complete copied localterm output/ligature regression suites. The keyless Web browser journey boots the shipped profile, writes files through real bottom and right PTYs, hides and reopens the bottom panel while preserving a shell variable, proves an isolated second browser page attaches the same PTY and observes that variable, changes terminal settings, and verifies right-Sheet plus bottom-panel behavior at compact width. The built client bundle is mechanically inspected through its ordinary build and the client CSS/purity tests cover global xterm styles and the single terminal protocol inline exception.

## Alternatives considered

**Poll terminal state through unary RPC.** Polling could reuse Typert calls, but it introduces latency and duplicate cursors, cannot provide ordered full-duplex input/output, and turns backpressure into repeated application requests.

**Expose only model terminal operations in the UI.** Those operations intentionally normalize retained output and wait for shell readiness. Making them an interactive transport would weaken their model-facing behavior and still omit resize and raw alternate-buffer bytes.

**Run localterm as a separate service or iframe.** This keeps its application intact but duplicates authentication, process ownership, sandbox resolution, Session selection, and lifecycle cleanup, and cannot compose as Workbench and bottom-panel plugins.

**Keep terminal registries inside each preset.** Child realms prevent a Host Consumer from resolving a Session's service through the Agent root, require every preset to repeat infrastructure rows, and make browser availability depend on model tool composition. One exact-Agent Host registry already provides the necessary isolation.

**Unmount or kill on panel close.** Unmounting drops terminal replay state and reconnects on every toggle; killing makes a layout gesture destructive. A zero-height mounted slot preserves the process and xterm state while consuming no vertical space.

## Consequences

Web sessions receive a direct, sandbox-policy-aware terminal in two responsive placements without changing model requests. Terminal providers gain a required resize operation and the terminal capability gains a raw attachment contract. Connection can host other identity-admitted full-duplex protocols without coupling them to its downlink codec. The costs are a large independently loaded xterm client bundle, two pinned addon patches, browser-local rather than Host-synchronized appearance preferences, raw uncompressed terminal output, and explicit cleanup for persistent terminals that users leave running.
