# Agent Note: 源码更新自动执行且版本单调递增

Status: implemented

[English](2026-08-22-automatic-monotonic-source-updates.md) | 中文

## 问题

更新清单曾把所有与已安装值不相等的 Registry 值都视为可用更新。因此，位于 `0.1.0-rc.11` 的源码检出会把 `0.1.0-rc.8` 作为目标，而 `^0.1.0` 等依赖范围也会显示为从已安装 `0.1.0` 发生变化。触发源码操作只会返回一条让操作者复制的命令，而不会应用更新。

## 决策

发行版目标使用语义化版本顺序。精确目标只有在大于已安装版本时才可操作；范围只有在其最小版本大于已安装版本时才可操作。较旧目标、相等目标，以及最小版本不高于已安装版本的范围，都不会触发 Badge 或操作，也不会呈现为版本迁移。

源码检出与 npm 全局安装使用仅所有者可访问的分离 Worker。源码 Worker 定位包含运行中应用清单的仓库，然后从该根目录依次运行 `git pull --ff-only`、`pnpm install` 与 `pnpm run build`。它在首次失败时停止；Git 无法快进时保留现有检出；移除类似凭据的环境变量；并把完成状态记录在 `$DSH_HOME/updates/status.json`。Nix、npx 与未知渠道仍由外部管理。

本决策部分取代[一致发行版决策](../architecture/2026-08-12-cohesive-distribution.zh.md)中的源码渠道例外。

## 测试

Provider 测试固定预发行版降级抑制、已满足的依赖范围、源码根目录发现、分离启动、命令顺序、失败即停止行为与仅所有者可读状态。组装后的 Web 快照使用本地 Registry，证明源码升级会提供“更新 DSH”、省略手动 Git 指引，并且不会把已测试的配套依赖范围呈现为升级。

## 考虑过的替代方案

**继续显示源码命令。** 拒绝，因为运行中的源码清单能够标识检出位置，分离 Worker 可以应用同一个有界操作，无需操作者使用终端。

**通过版本字符串不相等来比较。** 拒绝，因为不相等无法区分升级与预发行版降级，也无法区分精确已安装版本与兼容依赖范围。

**更新前重置或变基源码检出。** 拒绝，因为更新器不得重写本地历史或丢弃工作。仅快进拉取会在不改变分叉历史的情况下失败。

## 后果

更新页面通过一个操作执行受支持的源码与 npm 全局更新，且绝不会提供语义上更旧的目标。源码更新可能因脏检出或分叉检出、缺少可执行文件、安装失败或构建失败而失败；Worker 会记录失败并保持历史不变。更新完成后仍需重启正在运行的 Harness 进程。
