# Agent Note: 菜单勾选标记位于尾部装饰项之前

Status: implemented

[English](2026-08-23-menu-check-before-trailing-adornment.md) | 中文

## Problem

已选中的 `Menu` 条目总是在持有方提供的完整标签之后追加勾选标记。下钻菜单的持有方把箭头放在标签内部，最终顺序变成标签、箭头、勾选标记。若把勾选标记移到整个标签之前，它又会靠近前置图标，无法让两个右侧指示项保持相邻。

## Decision

`MenuItem.trailing` 承载下钻箭头等非交互式条目装饰项。`Menu` 依次渲染前置图标、弹性标签、选中勾选标记和 `trailing`；未选中的条目省略勾选标记，但装饰项位置不变。Factory 的新建会话任务、流程和具名流程条目通过该插槽呈现箭头，不再把箭头嵌入标签。

## Alternatives considered

**由每个持有方自行渲染勾选标记。** 持有方必须禁用 `selectedId`、复制规范选中标记，并失去共享的顺序规则。

**检查或重排标签子节点。** `label` 是不透明的 `ReactNode`；依赖其内部标记会让 Menu 行为因持有方而异且容易失效。

**在标签之前渲染勾选标记。** 这样只是在 DOM 顺序上解决问题，却会把选中状态移离右侧控件，并破坏没有箭头的普通条目布局。

## Consequences

下钻条目统一显示为勾选标记在前、箭头在后；普通已选条目仍保留尾部勾选标记。可选字段扩展了 `MenuItem`，不改变现有调用方。原子组件和组装后的 Factory 测试固定该标记顺序。
